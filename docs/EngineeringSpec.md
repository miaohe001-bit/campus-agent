# Campus Agent Engineering Spec

## 1. Product Summary

Campus Agent is a web dashboard for campus recruitment. It helps a student maintain goals, discover recruitment campaigns, track applications, manage schedules, and generate an AI daily plan.

The core product question is:

> What should the user do today?

The MVP should not try to automate job applications, reply to emails, or run multiple autonomous agents.

## 2. Design Principles

- Single Loop Agent: one agent is responsible for reasoning and planning.
- Database as source of truth: all business state lives in the database.
- Stateless Planner: each plan is computed from current database state and today's available time.
- Event driven: external changes become Recruitment Events.
- Engineering handles determinism: CRUD, retries, reminders, permissions, scheduling, and validation are code.
- Agent handles uncertainty: semantic understanding, prioritization, tradeoffs, and planning are model tasks.

## 3. System Architecture

```text
Web Dashboard
  -> Runtime Orchestrator
  -> Planner
  -> Tool Dispatcher
  -> Business Services
  -> Database
```

Side systems:

```text
Email Sync -> Recruitment Event -> Business Services
Scheduler -> Reminder Service
```

The Planner does not call the database. It requests facts and writes decisions through tools.

## 4. Core Business Objects

### Goal

Stores user job-search preferences:

- graduation year
- target positions
- target cities
- target industries
- target companies
- company priority: Dream, Target, Safe

### Campaign

Represents a recruitment campaign, not just a company.

Examples:

- Tencent 2027 Fall Official Batch
- ByteDance Early Batch

### Application

Represents one applied position. One company campaign can have multiple Applications.

Stages:

- submitted
- assessment
- written_test
- interview_1
- interview_2
- interview_3
- cross_interview
- hr_interview
- offer
- failed

### RecruitmentEvent

Append-only record of something that happened.

MVP event types:

- application_submitted
- assessment_received
- assessment_completed
- written_test_scheduled
- interview_scheduled
- interview_rescheduled
- interview_canceled
- offer_received
- rejected
- deadline_updated

### Schedule

Represents a time-bound event:

- application deadline
- assessment deadline
- written test
- interview
- offer response deadline
- custom item

### Todo

Represents a daily action generated by Planner or added by user.

Todo states:

- pending
- completed
- expired

## 5. Runtime

Runtime coordinates one agent run.

Runtime lifecycle:

```text
Trigger
  -> Build Context
  -> Planner
  -> Tool Call if needed
  -> Update Context
  -> Planner
  -> Validate Result
  -> Save Result
  -> Return Response
```

Runtime components:

- Context Builder: selects relevant business state.
- Loop Controller: controls max loop count and stop conditions.
- Tool Dispatcher: executes tool calls.
- Result Validator: checks strong rules.
- Response Generator: returns final structured response.

MVP max loop count: 5.

Runtime must not contain recruitment-specific business rules such as interview stage transitions. Those belong in Business Services.

## 6. Planner

Planner generates today's todos from Planning Context.

Input:

- user goal
- active applications
- upcoming schedules
- recent recruitment events
- yesterday todos and completion status
- today's available minutes

Output:

- max 3 todos
- estimated duration
- related application or campaign
- priority order
- business reason
- decision trace for debugging

Rules:

- Deadline tasks come first.
- Upcoming interviews and written tests are high priority.
- Active pipeline items beat new applications.
- Dream companies are higher priority than Target and Safe.
- Yesterday unfinished todos are reconsidered, not blindly copied.
- Total estimated time must not exceed available minutes.
- Duplicate todos are forbidden.

Planner output must be schema-validated before saving.

## 7. Tool Calling

Tools are the only interface between Planner and business state.

MVP tools:

- `get_planning_context(user_id, date)`
- `save_today_plan(user_id, date, todos)`
- `validate_plan(user_id, date, available_minutes, todos)`
- `mark_todo_completed(todo_id, completion_source)`
- `update_available_time(user_id, date, available_minutes)`
- `get_application_detail(application_id)`
- `create_schedule(input)`

Tool rules:

- Tools expose business actions, not SQL.
- Write tools must be idempotent.
- Tool errors are returned to Runtime, not hidden.
- Planner decides which tool is needed; Runtime executes it.

## 8. Event Flow

External changes become Recruitment Events.

Example:

```text
Email received
  -> parse recruitment event
  -> create RecruitmentEvent
  -> update Application
  -> create or update Schedule
  -> trigger Planner if needed
```

Events are append-only. New facts create new events.

Rejected event:

- set Application stage to failed
- cancel related future todos
- trigger replanning

Interview rescheduled event:

- update Schedule
- preserve change log
- trigger replanning

## 9. API Overview

Recommended MVP endpoints:

- `GET /goals`
- `PATCH /goals`
- `GET /campaigns`
- `GET /applications`
- `POST /applications`
- `PATCH /applications/{id}`
- `GET /todos?date=YYYY-MM-DD`
- `POST /planner/run`
- `PATCH /todos/{id}`
- `GET /schedules`
- `POST /schedules`
- `PATCH /schedules/{id}`
- `GET /events`

Response format:

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

## 10. MVP Development Plan

Phase 1: project scaffold, database, basic API.

Phase 2: Goal, Campaign, Application, Schedule, Todo CRUD.

Phase 3: Recruitment Event service and deterministic state updates.

Phase 4: Planning Context tool and RuleBasedPlanner.

Phase 5: Runtime and LLM Planner behind the same Planner interface.

Phase 6: Web dashboard pages.

Phase 7: mock email event import.

Phase 8: real email sync and browser notifications.

## 11. Non-Goals

MVP does not include:

- Multi-Agent
- long-term memory
- auto application submission
- auto email reply
- automatic interview scheduling
- external calendar sync
- resume generation
- interview coaching
